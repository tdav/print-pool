# Board and admin panel

[← back to README](../README.md) · [Русская версия](ru/agent.md)

The agent is a C# program on .NET nanoFramework 1.18 for the ESP32-S3 board (firmware target `ESP32_S3_OCTAL`).

## Two modes

**Setup mode.** The board raises its own Wi-Fi network `MyPrintAgent` (password `printagent`); the panel opens from a phone at `http://192.168.4.1/`. The mode starts when:

- there are no settings yet;
- the saved Wi-Fi network could not be joined within 60 seconds;
- the BOOT button was held for 3 seconds;
- the program crashed at start-up three times in a row.

**Work mode.** The board is connected to the router, polls the backend and prints. The panel is available at the board's address on the network and at `http://myprintagent.local/`.

The LED blinks slowly in work mode and fast in setup mode.

## Admin panel

A single page served by the board itself, laid out for a phone. The panel interface is in Russian.

| Section | Contents |
|---|---|
| Status | Mode, Wi-Fi, backend link, printer status, last job, board time |
| Device ID | The GUID the backend uses to address jobs; "Copy" and "Create new" buttons |
| Printer | Name, IP address, port, line width, printer ID; "Check connection", "Test print" |
| Printer scan | Probes an address range on the printer port; a found address is picked with a button |
| Wi-Fi network | Network name and password |
| Backend | Address and polling period |

Changes are applied with the "Save and reboot" button.

**Printer ID** is generated by the board. It stays the same while the printer's IP address and port do not change; a new one is generated when either changes. The printer name is for people and does not affect printing.

**Test print** prints a `1234567890…` ruler across the configured line width, which shows whether the width is right.

**Printer scan** probes one address in about a second and a half: 254 addresses take about 7 minutes. Printing during a scan is delayed by up to 2 seconds.

## Settings

Stored as a JSON file on the board's internal flash: device ID, Wi-Fi name and password, backend address, polling period, printer name, ID, IP address and port, line width.

Values for a new board are in `firmware/PrintAgent/Defaults.cs`; the Wi-Fi name and password are in `Secrets.cs` (not in Git).

## Failure behaviour

| What happened | What the board does |
|---|---|
| Printer is off, out of paper, or the cover is open | The job immediately gets `Failed` with a reason; the queue does not pile up |
| Power was lost while printing | After power-up it reports `REBOOT_DURING_PRINT` and does not print the receipt again |
| Backend is unreachable | Waits and retries; the outcome of a printed receipt is delivered once the link is back |
| Backend rejected an outcome with 400 three times in a row | Stops retrying that outcome and takes the next job |
| The job could not be parsed | `BAD_JOB` |

The print journal is kept in two files: the "started" mark and the outcome. Writing the outcome does not erase the mark, so a power cut in the middle of a write does not leave the board without a record of the printed receipt.

## Time

After joining Wi-Fi the board waits up to 10 seconds for its clock to synchronize with the internet and carries on either way. If the clock is not synchronized, the receipt time is taken from the job — the backend puts it there.

## Board quirk: USB

Any program on a computer that opens the board's COM port reboots it: that is how the built-in USB of the ESP32-S3 works. Powered from a power adapter with no computer attached, this does not happen.
