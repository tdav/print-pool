# Ограничения и открытые вопросы

[← к оглавлению](../README.md)

Проект задуман как пробный. Ниже — что в нём сознательно упрощено, что не проверено и что стоит решить до установки у клиентов.

## Сознательные упрощения

- **Задания в памяти.** Перезапуск бэкенда стирает очередь и историю.
- **Нет авторизации.** Любой в локальной сети может добавить задание или открыть панель платы и изменить настройки.
- **Только HTTP.** Между отправителем, бэкендом и платой нет шифрования.
- **Пароль Wi-Fi на плате хранится открытым текстом.**
- **Сеть настройки у всех плат одинакова:** `MyPrintAgent` с паролем `printagent`.
- **Часовой пояс чеков зашит в программу:** UTC+5. Для другого пояса нужна правка `AgentConfig.CreateDefault`.
- **Только латиница на чеках.**
- **Повторной печати нет.** Задание с ошибкой само не повторяется — решение за отправителем.

## Не проверено

- Сверка часов платы с интернетом: в сети, где шла разработка, шлюз не выпускал плату наружу, и время всегда бралось с бэкенда.
- Отказ `BAD_JOB` на плате для заданий `kitchen` и `bill`: бэкенд не даёт создать задание, которое его вызвало бы.
- Счёт на 60 позиций: хватит ли памяти платы на разбор.
- Чек при ширине строки 32 знака и тестовая печать с линейкой — на бумаге.
- Поиск принтеров по полному диапазону из двух подсетей (508 адресов) и страница поиска в браузере.
- Отключение роутера во время работы.
- Смена ID устройства без перезагрузки платы.
- Название и ID принтера тестами не покрыты.

## Известные недостатки

- **Панель замирает примерно на 23 секунды**, когда принтер выключен: запрос состояния ждёт ответа принтера.
- **Время бэкенда в задании на плате хранится в 32-битном числе:** хватит до 19 января 2038 года.
- **ID принтера меняется вместе с адресом.** Если тому же принтеру роутер выдаст другой IP, после правки адреса в панели ID будет новым.
- **ID принтера бэкенду не передаётся:** он только хранится на плате и виден в панели.

## Что решить перед установкой у клиентов

1. Защита панели платы: PIN или пароль.
2. Уникальное имя сети настройки для каждой платы.
3. Авторизация API бэкенда и HTTPS, если бэкенд доступен не только из локальной сети.
4. Хранение заданий в базе данных, если нужна история после перезапуска.
5. Часовой пояс заведения, если он не UTC+5.
