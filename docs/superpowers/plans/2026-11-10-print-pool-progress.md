## Отчёт пробного запуска

Заполняют задачи 1.2–1.4.

### Принтер, проверено с компьютера 2026-11-10 (часть задачи 1.2, без платы)

- TCP на `192.168.1.153:9100` открывается.
- Запросы состояния отвечают по одному байту, принтер исправен и с бумагой:

| Запрос | Ответ | Двоично |
|---|---|---|
| `10 04 01` | `0x16` | `00010110` |
| `10 04 02` | `0x12` | `00010010` |
| `10 04 03` | `0x12` | `00010010` |
| `10 04 04` | `0x12` | `00010010` |

- `PrinterStatus.Decode(0x12, 0x12)` возвращает «готов» — стандартная расшифровка подходит для состояния «всё в порядке». Ответы при открытой крышке и без бумаги ещё не сняты.
- Пробный чек из 12 строк (все типы, включая QR и отрезку; 425 байт) собран настоящим `EscPosBuilder` и отправлен; после печати состояние то же. Заказчик подтвердил 2026-11-10: чек напечатан верно — ширина 48 символов подходит, QR читается, отрезка работает. Тип `qr` в формате остаётся.
### Плата: точка доступа, файл, JSON, GUID — страница `http://192.168.4.1/`, снимок от заказчика 2026-11-10 (задачи 1.3 и 1.4)

- **Точка доступа работает.** Сеть `PrintAgent-SPIKE` (WPA2), телефон подключился, страница открылась. Понадобилась одна перезагрузка после сохранения настроек точки (`boots=2`). Порядок: интерфейс типа `WirelessAP` (на странице тип 72; клиентский `Wireless80211` — 71) → `EnableStaticIPv4("192.168.4.1", "255.255.255.0", "192.168.4.1")` → `WirelessAPConfiguration.GetAllWirelessAPConfigurations()[ap.SpecificConfigId]` → `Options = Enable | AutoStart`, `Ssid`, `Password`, `Authentication = WPA2`, `MaxConnections` → `SaveConfiguration()` → `Power.RebootDevice()`. Признак готовности после перезагрузки: `Options == (Enable | AutoStart)` (число 6), имя сети совпадает, адрес интерфейса `192.168.4.1`.
- **DHCP:** `new DhcpServer()`, `CaptivePortalUrl`, `Start(IPAddress.Parse("192.168.4.1"), new IPAddress(new byte[]{255,255,255,0}), 1200)` — телефон получил адрес.
- **Веб-сервер:** `new WebServer(80, HttpProtocol.Http)`, событие `CommandReceived`, ответ через `WebServer.OutPutStream(e.Context.Response, text)`, адрес запроса в `e.Context.Request.RawUrl`.
- **Диск:** `I:`, файл `I:\имя` пережил перезагрузку (`File.Exists`, `ReadAllText`, `WriteAllText`). `DriveInfo.TotalSize` возвращает `-1`.
- **GUID:** `Guid.NewGuid().ToString()` даёт обычный вид `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`.
- **JSON, главное:** разбор **чувствителен к регистру имён**. Класс со свойствами, названными в точности как ключи (`jobId`, `lines`, `type`, …), разобран верно, все 7 строк. Класс со свойствами `JobId`/`Lines` получил пустые значения без исключения — молчаливый отказ. Свойства для разбора называть как ключи JSON.
- Неизвестное поле в JSON (`unknownField`) исключения не вызывает. Отсутствующие поля остаются `null`/`False`/`0`.
- Оборванный JSON бросает `DeserializationException`.
- `JsonConvert.SerializeObject` пишет свойства под их именами; обратный разбор сходится.
- **Память:** нативная всего 8 701 371, свободно 1 350 915; управляемой свободно 7 163 628 байт. Запас большой.
- **Не проверено:** возврат из точки доступа в режим клиента, подключение к Wi-Fi роутера, HTTP-клиент, работа страницы при включённом мобильном интернете, ответы принтера без бумаги и с открытой крышкой.

- Пробная программа `firmware/spike/ApSpike` (точка доступа `PrintAgent-SPIKE`, DHCP, веб-страница, файл, JSON, GUID, память) собрана и загружена на плату 2026-11-10; плата отвечает по USB. Результаты получены, см. выше.
- При сборке: `AuthenticationType` неоднозначен между `System.Net` и `System.Net.NetworkInformation` — писать полное имя.
- Способ запуска кода Core с компьютера: `Add-Type -Path firmware\PrintAgent.Core\*.cs` в PowerShell 7.

## Выводы для следующих задач

- Сборка .NET-проектов идёт на SDK 10 через `global.json` в корне.
- Прошивка собирается и загружается одной командой: `firmware\build.ps1 -Project <папка> -Port COM5`; `-NoDeploy` — только образ. Библиотеки берутся строго из `packages.config` проекта, общая папка пакетов — `firmware\packages`.
- `string.StartsWith(string)` в общем коде Core запрещён: на .NET 10 он зависит от культуры, на плате — порядковый. Префиксы сравнивать посимвольно.
- Пока один агент пишет файлы в `firmware/PrintAgent.Core*`, общий тестовый проект у другого может не собираться; точечный прогон: `dotnet test firmware/PrintAgent.Core.Tests --filter FullyQualifiedName~<Класс>`.
- Бэкенд слушает только IPv4 (`0.0.0.0:5080`): с этого же компьютера обращаться по `127.0.0.1`, адрес `localhost` может уйти на IPv6 и не ответить.
- Работающий бэкенд держит файлы сборки: перед `dotnet build` останавливать его по PID.
- Контракт метода итога ужесточён: `deviceId` и `success` обязательны, `error` не длиннее 200 символов, тело не больше 2048 байт. Клиент прошивки (6.2) обязан всегда слать `success`.
- `JobJournal.OnBoot` возвращает `null` только когда записи нет или в ней нет ID задания; любое состояние, кроме `finished`, даёт `REBOOT_DURING_PRINT`.
- Строка `Co-Authored-By` в коммитах субагентов называет их собственную модель (Sonnet 5.5); в первых четырёх коммитах задач по моему указанию стоит Fable 5.2, хотя код писали субагенты на Sonnet.
- Вывод ошибок в PowerShell (`ErrorDetails.Message`) экранирует кириллицу сам; судить о кодировке ответа только по сырым байтам.
- Пакет поддельного времени для тестов бэкенда: `Microsoft.Extensions.TimeProvider.Testing` 10.11.0.
