# Пул печати: бэкенд и агент на ESP32-S3

Дата: 2026-11-10. Статус: утверждено заказчиком 2026-11-10, редакция 2.

Редакция 2: заказчик заменил схему. Вместо WT32-ETH01 с прямым кабелем к принтеру — имеющаяся ESP32-S3 по Wi-Fi и принтер, включённый кабелем LAN в сеть. Агент обращается к принтеру по IP-адресу и порту из настроек.

## Зачем

Нужно печатать чеки на принтере Xprinter (USB + LAN) по заданиям, которые приходят от других сервисов. Между сервисами и принтером стоят два звена:

- **бэкенд** — хранит очередь заданий для каждого устройства;
- **агент** — плата ESP32-S3: забирает задания, собирает из них чек и отправляет на принтер по сети.

Проект тестовый. Позже его логику перенесут в большой проект, где задания будут лежать в таблице базы данных.

## Схема

```
сервис-отправитель ──HTTP──> бэкенд (.NET 10, Swagger)
                                 ^
                                 │ HTTP, опрос раз в 5 с
                                 │
        телефон ──Wi-Fi──> ESP32-S3 (агент, nanoFramework)
       (админ-панель)            │
                                 │ Wi-Fi → роутер → кабель LAN
                                 │ TCP на IP и порт из настроек, ESC/POS
                                 v
                          Xprinter XP-Q80
```

Агент всегда сам обращается к бэкенду и к принтеру. Бэкенд к агенту не подключается: так схема работает из любой сети, когда бэкенд переедет в интернет.

Агент и принтер должны быть в одной сети: принтер включён кабелем в тот же роутер, к Wi-Fi которого подключается плата.

## Цели

1. Бэкенд на .NET 10 с четырьмя методами и Swagger.
2. Агент на ESP32-S3, написанный на C# (.NET nanoFramework).
3. Первичная настройка агента с телефона через его собственную сеть Wi-Fi.
4. Админ-панель, удобная на телефоне: в ней задаются IP-адрес и порт принтера и видно его состояние.
5. У каждого агента постоянный ID в виде GUID; по нему бэкенд отдаёт задания.
6. Агент сообщает бэкенду результат каждой печати: успех или причина ошибки.

## Чего не делаем

- База данных. Задания хранятся в памяти бэкенда и пропадают при его перезапуске.
- Авторизация и HTTPS. Тестовая версия работает по HTTP без ключей; админ-панель без пароля.
- Кириллица и другие алфавиты. Чеки только латиницей (ASCII).
- Картинки и логотипы на чеке.
- Автоматический повтор неудавшейся печати.
- Интерфейс для просмотра очереди. Достаточно Swagger.
- Несколько принтеров на одном агенте. Один агент — один принтер.

## Что считается провалом, даже если всё «работает»

- Один чек напечатан дважды.
- Чеки напечатаны не в том порядке, в котором добавлены.
- После ошибки (нет бумаги) накопленные задания вылетают пачкой без ведома отправителя.
- Тестовый бэкенд без авторизации выставлен в интернет.
- Агент после смены пароля Wi-Fi становится недоступен для настройки.
- Админ-панель на телефоне требует масштабировать страницу или прокручивать её вбок.

## Ограничения

- Плата агента — имеющаяся ESP32-S3-WROOM-1 N16R8 (16 МБ flash, 8 МБ PSRAM). На ней уже стоит nanoFramework 1.18.0.84, прошивка `ESP32_S3_OCTAL`; в ней есть Wi-Fi, сокеты и файловая система.
- Плата подключена к компьютеру через разъём USB, порт COM5.
- Расширение nanoFramework в Visual Studio не установлено. Сборка агента идёт способом, который уже работает для `Blink`: компилятор `csc`, пакет `nanoFramework.Tools.MetadataProcessor.CLI`, склейка `.pe` в образ, загрузка через `nanoff` (см. `Blink/flash.ps1`).
- Вывод отладочных сообщений с платы без расширения Visual Studio недоступен. Состояние агента должно быть видно другими средствами: в админ-панели и светодиодом TX (GPIO43).
- Стиль кода заказчика: комментарии и сообщения коммитов на русском; приватные поля без префикса `_`, обращение через `this.`; без лишних private-методов-помощников.
- В модальных окнах админ-панели кнопки справа, основная кнопка крайняя справа.
- Тесты: перед написанием любых тестов задать заказчику вопрос «Нужно ли написать тесты для этого кода?» и ждать ответа.

## Риски и пробный запуск

Прежний главный риск (Wi-Fi и Ethernet одновременно на WT32-ETH01) снят сменой схемы. Остаются три вещи, которые на этой плате не проверялись. Их проверяет короткий пробный запуск до основной работы:

1. Собственная точка доступа Wi-Fi с веб-страницей (в nanoFramework для этого есть образец «WiFi Soft AP»).
2. TCP-соединение с принтером по его IP и порту, печать одной строки, чтение состояния принтера (бумага, крышка) и встроенная команда QR-кода.
3. Запись и чтение файла во внутренней памяти платы.

Попутно определяется набор NuGet-пакетов nanoFramework (Wi-Fi, точка доступа, сокеты, HTTP, JSON, файловая система).

Код пробного запуска одноразовый и в проект не идёт. Если какой-то пункт не выполняется, работа останавливается и заказчик получает описание проблемы с вариантами.

## Бэкенд

ASP.NET Core на .NET 10, один проект. Задания в памяти, по отдельной очереди на каждое устройство.

### Методы

| № | Метод | Кто вызывает | Что делает |
|---|---|---|---|
| 1 | `POST /api/jobs` | сервис-отправитель | Добавляет задание для устройства. Возвращает ID задания (GUID). |
| 2 | `GET /api/devices/{deviceId}/jobs/next` | агент | Отдаёт следующее задание устройства или «заданий нет». |
| 3 | `POST /api/jobs/{jobId}/result` | агент | Принимает итог печати: успех или текст ошибки, вместе с ID устройства. |
| 4 | `GET /api/jobs/{jobId}` | сервис-отправитель | Показывает состояние задания. |

Методы 1–3 назвал заказчик. Метод 4 добавлен исполнителем: без него отправитель не узнает, напечатан ли чек.

### Состояния задания

`Queued` (в очереди) → `Dispatched` (выдано агенту) → `Printed` (напечатано) или `Failed` (ошибка, с текстом причины).

### Правила

- Агент получает по одному заданию. Пока у устройства есть задание в состоянии `Dispatched`, метод 2 повторно отдаёт его же, а не следующее. Так сохраняется порядок и исключается потеря задания при обрыве связи.
- Результат принимается только для задания в состоянии `Dispatched` и только от того устройства, которому оно выдано. Иначе ответ с ошибкой.
- Задание в состоянии `Dispatched` дольше заданного времени (по умолчанию 60 с, настраивается) получает `Failed` с причиной «нет ответа от устройства».
- Исключение: если после такого `Failed` по таймауту тот же агент всё же прислал итог, он принимается и заменяет состояние. Иначе чек, напечатанный на 61-й секунде, останется с ложной ошибкой.
- После `Failed` задание само не повторяется. Следующие задания очереди продолжают выдаваться.
- Задание отклоняется при добавлении, если в нём больше 100 строк, тело больше 8 КБ или есть неизвестный тип строки.
- Устройства заранее не регистрируются: очередь создаётся при первом задании для нового ID.
- Бэкенд слушает на всех сетевых интерфейсах на постоянном порту, по HTTP: агент обращается к нему по сети.

Решения этого раздела, кроме трёх методов и опроса раз в 5 секунд, приняты исполнителем.

## Формат задания

JSON со списком строк. Как выглядит чек, решает отправитель; агент умеет печатать только перечисленные типы строк.

```json
{
  "deviceId": "3f2a9c1e-0000-0000-0000-000000000000",
  "lines": [
    { "type": "text", "text": "CAFE ROMASHKA", "align": "center", "bold": true, "size": 2 },
    { "type": "divider" },
    { "type": "pair", "left": "Plov 1 x 35 000", "right": "35 000" },
    { "type": "pair", "left": "TOTAL", "right": "45 000", "bold": true },
    { "type": "qr", "value": "https://example.com/c/1045" },
    { "type": "feed", "lines": 3 },
    { "type": "cut" }
  ]
}
```

| Тип | Поля | Печать |
|---|---|---|
| `text` | `text`, `align` (left/center/right), `bold`, `size` (1 или 2) | Строка текста |
| `pair` | `left`, `right`, `bold` | Левая часть у левого края, правая у правого |
| `divider` | — | Линия из дефисов на всю ширину |
| `qr` | `value` | QR-код по центру, встроенной командой принтера |
| `feed` | `lines` | Пустые строки |
| `cut` | — | Отрезка бумаги |

QR-код рисует сам принтер по своей команде. Если принтер её не поддерживает, тип `qr` убирается из формата, и бэкенд такие задания отклоняет.

Ширина строки — 48 символов (обычный шрифт на бумаге 80 мм; уточняется по самотесту принтера). Символы вне ASCII агент заменяет на `?`.

Формат выбрал исполнитель по просьбе заказчика; заказчик задал только «латиница».

## Агент

Программа на C# под nanoFramework. Два режима.

### Режим настройки

Включается, если:

- файла настроек нет;
- к сохранённой сети Wi-Fi не удалось подключиться за 60 секунд;
- кнопку BOOT на плате держали нажатой 3 секунды (принудительный вход).

Во втором случае агент через 5 минут без сохранения настроек перезагружается и снова пробует Wi-Fi, чтобы временный сбой роутера не оставил его в режиме настройки навсегда.

В режиме настройки агент поднимает свою сеть Wi-Fi с постоянным именем `MyPrintAgent` и паролем `printagent` (решение заказчика от 2026-11-10; прежний вариант с знаками MAC-адреса отменён). Телефон подключается к ней и открывает `http://192.168.4.1/`.

Проверка принтера в этом режиме недоступна: пока агент раздаёт свою сеть, он не в сети роутера и принтера не видит. Она работает после перезагрузки в рабочий режим.

### Рабочий режим

1. Подключиться к Wi-Fi.
2. Запустить админ-панель по адресу платы в сети роутера.
3. Раз в период опроса (по умолчанию 5 с) запросить у бэкенда задание по своему ID.
4. Получив задание: открыть TCP-соединение с принтером по IP и порту из настроек, спросить состояние, собрать чек в команды ESC/POS, отправить.
5. Сообщить бэкенду итог с ID задания и ID устройства.
6. Если итог не удалось передать, повторять передачу и не брать следующее задание, пока итог не доставлен.

**Защита от двойной печати при перезагрузке.** Перед отправкой чека на принтер агент записывает в память платы ID задания с пометкой «начато», после печати — итог. При включении агент смотрит на эту запись:

- есть итог, который не доставлен, — сначала доставляет его;
- есть «начато» без итога — сообщает `Failed` с причиной «перезагрузка во время печати» и чек заново не печатает.

### Админ-панель

Одна веб-страница, которую отдаёт сама плата. Доступна в обоих режимах: в режиме настройки по `http://192.168.4.1/`, в рабочем — по адресу платы в сети роутера.

**Требования заказчика к виду:** адаптивная вёрстка, на телефоне выглядит и ведёт себя как обычное мобильное приложение.

Что это означает на деле (уточнение исполнителя):

- Вёрстка от телефона: одна колонка шириной от 320 пикселей, на широком экране содержимое по центру. Без прокрутки вбок и без необходимости масштабировать.
- Крупные элементы управления: поля и кнопки высотой не меньше 44 пикселей.
- Правильная клавиатура телефона: цифровая для IP-адреса, порта и периода опроса; для адреса бэкенда — клавиатура URL.
- Системный шрифт телефона, светлая и тёмная тема по настройке телефона.
- Сохранение и проверки без перезагрузки страницы, с понятным сообщением о результате.
- Всё в одном файле: стили и скрипты внутри страницы, без обращений в интернет. В режиме настройки интернета у телефона нет.
- Тексты на русском.

**Состав:**

- **Состояние.** Режим агента, подключение к Wi-Fi и адрес платы, связь с бэкендом, состояние принтера (отвечает ли, есть ли бумага, закрыта ли крышка), последнее задание и его итог.
- **ID устройства (GUID).** Создаётся автоматически при первом запуске, показывается с кнопкой «Скопировать». Кнопка «Создать новый ID» с подтверждением: после неё бэкенд перестанет отдавать этому агенту задания, адресованные старому ID.
- **Принтер.** IP-адрес и порт (по умолчанию 9100). Кнопки «Проверить связь» и «Тестовая печать».
- **Сеть.** Имя и пароль Wi-Fi.
- **Бэкенд.** Адрес бэкенда, период опроса.
- **Кнопка «Сохранить и перезагрузить».**

**Раскладка, одобренная заказчиком по макету.** Блоки идут сверху вниз в порядке перечисления выше. В шапке — название, адрес платы и метка режима. Состояния Wi-Fi, бэкенда и принтера показаны цветными метками. IP-адрес и порт стоят в одной строке. Второстепенные кнопки прижаты вправо. Внизу одна основная кнопка «Сохранить и перезагрузить» на всю ширину. В режиме настройки кнопки проверки принтера отключены с пояснением, что они заработают после подключения к Wi-Fi.

Заказчик задал: своя сеть Wi-Fi для настройки, настройка с телефона, GUID, проверка принтера, IP и порт принтера в настройках, адаптивность. Остальное определено исполнителем.

### Файл настроек

JSON во внутренней памяти платы: ID устройства, имя и пароль Wi-Fi, адрес бэкенда, IP-адрес и порт принтера, период опроса. Читается при каждом включении.

Пароль Wi-Fi хранится открытым текстом. Для тестового проекта это принято; для большого проекта нужно пересмотреть.

### Ошибки печати

Агент сообщает одну из причин: принтер не отвечает, нет бумаги, открыта крышка, задание не разобрано, сбой при передаче. Умеет ли именно эта модель отдавать состояние бумаги и крышки по сети, выяснит пробный запуск; если нет, остаются «не отвечает» и «сбой при передаче».

**Поведение, пока принтер не готов (решение исполнителя, заказчик не ответил):** агент продолжает забирать задания, и каждое сразу получает `Failed` с причиной. Очередь не копится и не печатается пачкой после заправки бумаги. Альтернатива — ждать готовности принтера и печатать накопленное — отклонена как противоречащая отказу от автоматического повтора.
