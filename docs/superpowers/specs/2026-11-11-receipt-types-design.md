# Типы чеков: кухня и счёт клиенту

Дата: 2026-11-11. Дополняет `2026-11-10-print-pool-design.md` (далее — базовая спека). Всё, что здесь не названо, остаётся как в базовой спеке.

Пометки: **[заказчик]** — сказано заказчиком; **[моё]** — решение автора спеки, заказчик его видел в переписке и не возразил либо не видел вовсе (тогда сказано отдельно).

## Зачем

Сейчас отправитель присылает бэкенду готовые строки чека: что печатать жирным, где черта, где отрезка. Вёрстку чека знает отправитель. Заказчику нужно наоборот: отправитель присылает **тип чека и данные заказа**, а как это выглядит на бумаге, решает плата. Тогда вид чека меняется в одном месте, и разные отправители печатают одинаково. **[заказчик]**

Типов два **[заказчик]**:

1. **Кухня** (`kitchen`) — заказ повару на приготовление.
2. **Счёт** (`bill`) — чек клиенту для оплаты, закрывает счёт.

Образцы заказчика (три фотографии чеков кафе) лежат в переписке; текстовые макеты ниже сделаны по ним.

## Цели

- Бэкенд принимает задание с типом чека и данными, проверяет данные по типу и отдаёт их плате без изменений.
- Плата по типу собирает чек и печатает его.
- Дату и время на чеке ставит плата по своим часам, сверенным с интернетом. Отправитель дату не присылает. **[заказчик]**
- Ширина строки принтера — настройка в админ-панели, а не число в коде. **[заказчик]**

## Чего не делаем

- **Логотип и любые картинки.** Первый вариант — только текст; картинка, возможно, появится позже. **[заказчик]**
- **Кириллицу.** Чеки печатаются латиницей; решение базовой спеки подтверждено заказчиком заново. Не-ASCII символы в данных плата по-прежнему заменяет на `?`. **[заказчик]**
- **Арифметику.** Ни бэкенд, ни плата не считают и не сверяют суммы: печатается то, что прислал отправитель. **[моё]**
- Фискальные функции, копии чека, повторную печать, выбор шрифта.

## Что считается провалом

- На чеке дата 1970 года или время в другом часовом поясе.
- Сумма на бумаге отличается от присланной (обрезана, сдвинута в чужую колонку, потеряла разряд).
- Название блюда обрезано без переноса: повар не видит, что готовить.
- Старый формат со строками перестал работать: на нём держатся тестовая печать и проверки базовой спеки.
- Задание неизвестного типа осталось без итога или напечаталось мусором.

## Контракт

### Добавление задания: `POST /api/jobs`

Тело — один из трёх видов. Предел тела 8 КБ, как раньше; он проверяется первым и даёт 413 ещё до разбора. Пределы таблицы ниже допускают тело больше 8 КБ (60 позиций по 100 знаков) — такое задание получает 413, а не 400.

**Кухня**

```json
{
  "deviceId": "3f2a1c9e-0000-0000-0000-000000000000",
  "type": "kitchen",
  "data": {
    "billNumber": "A20",
    "table": "12",
    "hall": "Siniy zal",
    "cashier": "Vlad",
    "items": [
      { "name": "SARBAST NEFILTR RAZLIV", "quantity": 1 }
    ]
  }
}
```

**Счёт**

```json
{
  "deviceId": "3f2a1c9e-0000-0000-0000-000000000000",
  "type": "bill",
  "data": {
    "title": "BEREZKA",
    "billNumber": "A20",
    "table": "12",
    "hall": "Siniy zal",
    "cashier": "Vlad",
    "items": [
      { "name": "MNOGO MYASA 40SM", "quantity": 1, "sum": 80000 },
      { "name": "SARBAST NEFILTR RAZLIV", "quantity": 9, "sum": 126000 }
    ],
    "subtotal": 321000,
    "servicePercent": 10,
    "serviceSum": 32100,
    "total": 353100,
    "currency": "sum"
  }
}
```

**Строки** — прежний формат базовой спеки: `{ "deviceId": "...", "lines": [...] }`. Поле `type` можно не указывать или указать `"lines"`. **[моё]**

Правила выбора вида **[моё]**:

| `type` | Обязательно | Запрещено |
|---|---|---|
| нет или `"lines"` | `lines` | `data` |
| `"kitchen"`, `"bill"` | `data` | `lines` |
| любое другое | — | ответ 400 |

### Проверка данных

Ответ 400 называет первое неверное поле. Пределы **[моё]**:

| Поле | Тип | Правило |
|---|---|---|
| `billNumber` | строка | обязательно, 1–20 знаков |
| `table` | строка | обязательно, 1–20 знаков |
| `hall` | строка | необязательно, до 40 знаков |
| `cashier` | строка | обязательно, 1–40 знаков |
| `title` (только счёт) | строка | необязательно, до 24 знаков |
| `items` | массив | обязательно, от 1 до 60 позиций |
| `items[].name` | строка | обязательно, 1–100 знаков |
| `items[].quantity` | целое | обязательно, от 1 до 9999 |
| `items[].sum` (только счёт) | целое | обязательно, от 0 до 999 999 999 |
| `subtotal`, `total` (только счёт) | целое | обязательно, от 0 до 999 999 999 |
| `servicePercent` (только счёт) | целое | необязательно, от 0 до 100, по умолчанию 0 |
| `serviceSum` (только счёт) | целое | необязательно, от 0 до 999 999 999, по умолчанию 0 |
| `currency` (только счёт) | строка | необязательно, до 8 знаков |

Суммы — целые числа без копеек. Верхний предел выбран так, чтобы число помещалось в 32-битное целое на плате и в колонку чека.

Соответствие `total = subtotal + serviceSum` и суммы позиций бэкенд **не проверяет** (см. «Чего не делаем»).

Необязательные поля **[моё]**: отсутствующая или `null` строка (`hall`, `title`, `currency`) хранится и отдаётся плате как пустая строка `""`, отсутствующее число (`servicePercent`, `serviceSum`) — как `0`. Плата не получает `null` ни в одном поле `data`.

Лишние ключи **[моё]**: неизвестные поля и поля «только счёт» в кухонном задании не считаются ошибкой, но отбрасываются — плате отдаются только поля из таблицы для данного типа.

Количество — только целое **[моё; заказчику задан вопрос о весовых позициях]**.

Не-ASCII символы бэкенд **не отклоняет**: это прежнее поведение, проверенное сценарием 10 базовой спеки.

### Выдача задания плате: `GET /api/devices/{deviceId}/jobs/next`

Ответ 200 теперь содержит тип:

```json
{ "jobId": "...", "type": "kitchen", "data": { ... } }
{ "jobId": "...", "type": "bill", "data": { ... } }
{ "jobId": "...", "type": "lines", "lines": [ ... ] }
```

`type` присутствует всегда, в том числе для заданий, добавленных без него. `data` содержит ровно поля таблицы проверки для своего типа, необязательные — со значениями по умолчанию (см. выше).

### Просмотр задания: `GET /api/jobs/{jobId}`

Добавляются поля `type` и `data` (или `lines`).

Остальные методы, коды ответов, состояния задания и правила таймаута не меняются.

## Вид чеков

`W` — ширина строки из настроек принтера (по умолчанию 48). Крупный шрифт — двойная ширина и высота, в строке помещается `W / 2` знаков; деление везде целочисленное, при нечётном `W` лишняя колонка остаётся пустой справа.

Общее правило для любой строки, собранной из данных **[моё]**: текст длиннее строки не обрезается, а переносится по знакам на следующие строки с тем же выравниванием. Это касается и строк шапки (`Stol No: ...` с длинным названием зала может не поместиться). Все тексты из данных проходят прежнюю очистку (`?` вместо не-ASCII).

Постоянные надписи — узбекские латиницей **[заказчик выбрал язык; сами слова — моё, заказчику предложено поправить]**: `Sana`, `Kassir`, `Hisob No`, `Stol No`, `Nomi`, `Soni`, `Summa`, `Xizmat`, `Jami`. Знака «№» в латинской таблице принтера нет, поэтому `No`. Надписи лежат в одном месте программы платы, чтобы язык менялся одной правкой.

Дата и время: `dd.MM.yyyy HH:mm` по часам платы с учётом часового пояса из настроек.

### Кухня

При `W = 48`:

```
                11.11.2026 22:53
                 Hisob No: A20
             Stol No: 12, Siniy zal
                  Kassir: Vlad

SARBAST NEFILTR RAZL...1
IV
MNOGO MYASA 40SM.......2
```

- Четыре строки шапки в порядке образца: дата, `Hisob No`, `Stol No`, `Kassir`. Обычный шрифт, каждая по центру **[моё; на образце шапка сдвинута вправо единым блоком]**. Если `hall` пуст, строка стола — `Stol No: 12`.
- Пустая строка.
- Каждая позиция — крупным шрифтом, жирно **[жирность — моё]**, строка шириной `W / 2`: название слева, количество справа, между ними точки, не меньше трёх. Если название не помещается в `W / 2 − длина количества − 3`, в первую строку идёт его начало, остаток переносится на следующие строки по `W / 2` знаков. Перенос — по знакам, как на образце **[заказчику предложен перенос по словам, он не выбрал его]**.
- Цен и итогов нет.
- Протяжка на 3 строки, отрезка.

### Счёт

При `W = 48`:

```
        BEREZKA                                   (крупно, по центру)

             Sana: 11.11.2026 23:08
                  Kassir: Vlad
                 Hisob No: A20
             Stol No: 12, Siniy zal
------------------------------------------------
Nomi                           Soni        Summa
------------------------------------------------
MNOGO MYASA 40SM                  1       80 000
SARBAST NEFILTR RAZLIV            9      126 000
KARTOFEL PO-DEREVENSKI S SOUS     2       30 000
OM
------------------------------------------------
                    Summa:               321 000
                    Xizmat: 10%           32 100
------------------------------------------------
   Jami: 353 100 sum                              (крупно, по центру)
------------------------------------------------
```

- `title`, если не пуст: крупно, жирно, по центру, затем пустая строка. Если он длиннее `W / 2` — обычным размером, жирно. Если пуст — названия нет.
- Четыре строки шапки по центру в порядке образца счёта, он **отличается** от кухонного: `Sana`, `Kassir`, `Hisob No`, `Stol No`. Обычный шрифт.
- Черта во всю ширину.
- Таблица из трёх колонок с одним пробелом между ними: название `W − 19` знаков слева, количество 5 знаков вправо, сумма 12 знаков вправо. Сначала строка заголовков `Nomi / Soni / Summa`, черта, затем позиции. Название длиннее колонки переносится по знакам на следующие строки; количество и сумма стоят в первой строке позиции. Строки таблицы — обычным шрифтом, не жирно.
- Суммы печатаются с пробелом между тройками разрядов: `126 000`.
- Черта, затем строка `Summa:` и строка обслуживания: надпись начинается с позиции `W / 2 − 4` (счёт позиций с нуля), сумма прижата к правому краю. Если при этом между надписью и суммой не остаётся хотя бы одного пробела, надпись сдвигается влево настолько, чтобы пробел был.
- Строка обслуживания **[моё]**: печатается, только если `serviceSum` больше нуля. Надпись — `Xizmat: N%`, а при `servicePercent`, равном нулю, — просто `Xizmat:`.
- Черта, строка `Jami: <total> <currency>` крупно, жирно, по центру. Если она длиннее `W / 2`, печатается обычным размером жирно. Если `currency` пуст — без валюты.
- Черта, протяжка на 3 строки, отрезка.

### Строки

Прежний формат. Черта и пары «лево — право» теперь тоже считаются от `W`.

## Плата

### Время

- При подключении к Wi-Fi плата ждёт сверки часов с интернетом (у `WifiNetworkHelper.ConnectDhcp` для этого есть параметр `requiresDateTime`). **[заказчик: сверка до начала работы]**
- Если Wi-Fi есть, а время за отведённые 60 секунд не получено, плата **не уходит в режим настройки**, а подключается без требования времени и работает дальше. **[моё, заказчик этого не видел]** Причина: сеть без интернета не должна останавливать тестовую печать и панель.
- Перед печатью чека типа `kitchen` или `bill` плата проверяет часы: год меньше 2024 означает, что время не сверено. Тогда чек не печатается, итог — ошибка `TIME_NOT_SYNCED`. **[моё, заказчик видел и не возразил]**
- Чеку типа `lines` время не нужно, он печатается всегда.
- Панель показывает в разделе «Состояние» текущее время платы или «не сверено».

### Настройки

Два новых поля в файле настроек, в `GET/POST /api/config` и в панели:

| Поле | Где в панели | По умолчанию | Правило |
|---|---|---|---|
| `lineWidth` | «Принтер» → «Ширина строки, знаков» | 48 | от 32 до 64 **[диапазон — моё]** |
| `utcOffsetHours` | «Состояние» или отдельный раздел «Время» → «Часовой пояс, часов от UTC» | 5 | от −12 до 14 **[моё]** |

Нижняя граница 32 — это бумага 58 мм. При меньшей ширине в таблице счёта не остаётся места на название блюда, а надписи итогов наезжают на суммы; в переписке заказчику называлась граница 24, она поднята по итогам проверки спеки.

Контрольные значения при `W = 32`: крупная строка 16 знаков, колонка названия в счёте 13 знаков, название в первой строке кухонной позиции — до `16 − длина количества − 3` знаков, надпись итогов начинается с позиции 12.

В файле настроек, записанном прежней версией, этих полей нет: тогда берутся значения по умолчанию.

Тестовая печать из панели получает строку-линейку из цифр длиной `W`: по ней подбирают ширину. Перенос линейки на вторую строку означает, что значение велико. **[моё]**

### Разбор задания

- Плата читает `type` и по нему собирает чек. Имена полей в классах разбора совпадают с ключами JSON буква в букву: разбор на плате чувствителен к регистру (правило из журнала базовой спеки).
- Неизвестный `type`, отсутствующие `data` или пустой список позиций дают итог с ошибкой `BAD_JOB`, как сейчас для неразобранных строк.
- Сборка чека по данным — чистая логика без обращения к железу; она живёт в `firmware/PrintAgent.Core` рядом с `EscPosBuilder`, чтобы проверяться на компьютере.

### Новые коды ошибок

`TIME_NOT_SYNCED` — добавляется к списку базовой спеки.

## Что остаётся исполнителю

- Имена и раскладка классов данных на бэкенде и на плате.
- Способ хранения `data` в задании на бэкенде (типизированные записи или дерево JSON), если отдаваемое плате совпадает с принятым.
- Точные формулировки сообщений 400.
- Размещение полей в панели, если соблюдены UI-правила базовой спеки (адаптивность, кнопки справа).
- Проверить на плате до написания кода: возвращает ли `ConnectDhcp(..., requiresDateTime: true, ...)` `false` при отсутствии интернета и продолжает ли прошивка сверять время позже сама; разбирает ли `nanoFramework.Json` вложенный объект `data` с массивом `items`.

## Тесты

По правилу заказчика тесты пишутся только после его подтверждения. Вопрос задаётся перед составлением плана. Если тесты нужны, обязательные случаи: каждая граница таблицы проверки; чек кухни и чек счёта при `W = 48` сверяются с макетами посимвольно, при `W = 32` и при нечётном `W` — с эталоном, выведенным из правил и контрольных значений выше; строка шапки длиннее `W`; `Xizmat: 100%` с суммой из 11 знаков при `W = 32`; перенос названия; `Xizmat` при нуле; `TIME_NOT_SYNCED`; старый формат без `type`.

## Проверка на железе

- Оба чека напечатаны на принтере заказчика, заказчик сверяет их с макетами.
- Чек счёта с названием длиннее колонки и с суммой 999 999 999.
- Смена `lineWidth` на 32 и обратно; линейка в тестовой печати.
- Дата и время на чеке совпадают с часами заказчика.
- Задание прежнего формата печатается как раньше.
